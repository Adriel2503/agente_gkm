Panorama: 2 endpoints, 4 tools

El LLM (gpt-4o-mini) decide cuándo llamar cada tool durante la conversación. Solo hay dos servicios externos por detrás.

RAG API (lectura)
POSTAPI_KIA_RAG_URL → /buscar

Solo buscar_vehiculo. Búsqueda semántica con pgvector. Resiliente: tiene retry + circuit breaker (es lectura, se puede reintentar).

Bitrix / Bitrix24 (escritura)
POSTBITRIX_API_URL · api_key en el body

Las 3 tools de cierre. Mismo endpoint; cambia el campo action (edit / task). Sin retry ni cache — idempotencia delegada al prompt.

Cada tool de cierre marca un evento de negocio

Tool 1 🔍 buscar_vehiculo

Busca modelos KIA por similitud semántica en el catálogo y devuelve hasta 3 modelos con toda su ficha.

Parámetro que recibe la tool (lo pasa el LLM)
ParámetroTipoRepresenta
query (requerido)stringTexto libre de búsqueda. Lo arma el agente desde lo que pide el cliente: "auto familiar", "SUV barato", "Picanto".

Qué hace la tool con eso

Es la única tool que recibe un solo parámetro. Lo envía al endpoint RAG y devuelve hasta 3 modelos con su ficha.

Única tool de lectura: si la red falla, reintenta y el circuit breaker la protege. No escribe nada en el CRM.

Ejemplo
Cliente
Busco una SUV familiar, no muy cara
AutoBot
Dejame ver opciones para vos…

El agente llama:

buscar_vehiculo(
  query = "SUV familiar económica"
)

→ POST /buscar con {"query":"SUV familiar económica"} → devuelve Sportage, Seltos, Sonet con precio y ficha, y el bot responde con esas opciones.

Tool 2 📅 agendar_cita · parámetros que recibe

Estos son los parámetros que el LLM le pasa a la tool. La tool los transforma y arma sola el payload (edit + task) hacia Bitrix.

Parámetros de la tool (los pasa el LLM)
ParámetroTipoRepresenta
resumenstringResumen de la charla al agendar
financing_requiredstring SÍ/NO¿Requiere financiamiento?
corporate_agreementstringConvenio corporativo
trade_in_vehiclestring SÍ/NO¿Entrega usado en parte de pago?
used_vehicle_brandstringMarca del usado
used_vehicle_modelstringModelo del usado
used_vehicle_yearstringAño del usado
used_vehicle_mileagestringKilometraje del usado
purchase_expectationstringExpectativa de compra
budget_descriptionstringPresupuesto textual
appointment_datetimestringFecha/hora de la cita (solo en esta tool)

Qué hace la tool con eso

Con esos 11 parámetros la tool dispara 2 POST a Bitrix:

  • edit — mapea los parámetros a los campos UF_CRM_* del lead.
  • task — recordatorio para el asesor. No usa parámetros del LLM: título, descripción y deadline son fijos.

No son parámetros de la tool

id_bitrix sale del contexto de la sesión, no del LLM. Los campos del payload (action, api_key, ID, STATUS_ID, UF_CRM_*) los arma el código, no la IA.

Tipos: la IA pasa todo como string. Lo que no aplica o no se conoce → "N.A".

  "UF_CRM_1728502747862": "Llamar - confirmar cita IA",
  "STATUS_ID": "Asignado a Vendedor (Sin Contacto)",
  "UF_CRM_1653688826": "SÍ",
  "UF_CRM_1653599755": "SÍ",
  "UF_CRM_1653605302623": "Toyota",
  "UF_CRM_1653605318164": "Corolla",
  "UF_CRM_1534532283": "2018",
  "UF_CRM_1534533297": "85000",
  "UF_CRM_1721064189466": "Comprar este mes",
  "UF_CRM_1774975288": "N.A",
  "SOURCE_DESCRIPTION": "Presupuesto: 25000 dólares | Cita: 2026-05-20 16:00 | Resumen: …"
}

Vuelca en el lead todo lo que entendió de María.

2 · action = task  ·  5s después · recordatorio del asesor 
{
  "action": "task",
  "api_key": "<APIKEY_BITRIX>",
  "ID": 78421,
  "TITLE": "Llamar - confirmar cita IA",
  "DESCRIPTION": "-",
  "DEADLINE": "2026-05-20 16:30:00"
}

Por qué van separados

  • edit = los datos del cliente. Lleva todos los UF_CRM_*.
  • task = recordatorio para el vendedor humano. Salvo el ID, todo es fijo.
  • El sleep(5s) entre ambos evita que la task llegue antes de que Bitrix procese el edit.
  • DEADLINE = ahora + 30 min: ventana para llamar, no la hora de la cita (esa va en el edit).

Tool 4 🚫 marcar_desistido · parámetros que recibe

Cierra el lead sin éxito comercial.

Parámetros de la tool

Ninguno

marcar_desistido() no recibe ningún parámetro del LLM. El agente solo decide cuándo llamarla.

La tool arma sola el payload edit: usa el id_bitrix del contexto de la sesión y el resto de los campos son fijos (status, razón "No respondió a la IA"). No crea task.

¿Cuándo se llama?

  • No responde tras 2 intentos de reformular
  • Rechaza cita y callback
  • Pide no ser contactado ("no me molesten")
Ejemplo
Lucía
No me interesa, no me escriban más
AutoBot
Entendido, Lucía. ¡Que tengas buen día!

El agente llama (sin argumentos):

marcar_desistido()

→ un solo edit con STATUS_ID = "Desistido". No crea task. Idempotente: una sola vez por conversación.

Lectura vs escritura
